# RealScale Terrain v1.3 — all eight presets: continuous terrain and depth-constrained caves

**Experimental! Not a stable release. Use brand-new test worlds, not existing v1.1 or v1.2 saves.**

## Diagnosis, confirmed from repository files

Seven procedural presets had `minecraft:flat_cache` exposed at the root of their final XZ height signal. Minecraft 1.21.1's `flat_cache` samples a single value per **4×4-block horizontal cell**. Using it unmodified as `final_density`'s height component gives terrain columns with a blocky four-block-scale profile, distinct from Minecraft's unavoidable one-block voxel geometry.

An initial v1.2 repair replaced 12 caches across Realism MAX with `cache_2d`. This eliminates one source of discontinuity, but introduced a **severe performance regression** in real-server spawn generation: complex splines and 3D cave density were evaluated far more often. One previous Realism MAX server run passed, but a later run stalled around 51% spawn-preparation and missed the 480-second deadline. Do **not** confuse a successful Gradle build with a successful, performant world generator.

## v1.3 mechanism

For each procedural preset `height_signal`:
```json
{"type":"minecraft:interpolated",
 "argument":{"type":"minecraft:flat_cache","argument": "... original 2D height expression ..."}}
```
This is a conceptual example; the actual files contain their complete original expressions.

The original coarse cached values remain fast to compute, but **the outer value is interpolated between adjacent noise-cell corners**. The interpolation occurs before the density is compared to the local Y gradient, so it avoids leaking a flat 4×4 sample directly into the final Minecraft block surface. `size_horizontal=1`, `size_vertical=1` remain unchanged, providing **4-block horizontal noise cells with per-block interpolated output**, not 4-block square terraces. Inside Realism MAX, `height_signal_raw` and the 2D component fields return to fast `flat_cache`, while the final height spline is interpolated, preserving v1.2's summit easing.

USGS Big Sur already uses continuous bilinear DEM interpolation at each requested meter. Its outer 96 m smoothstep border blends toward the newly smoothed Realism MAX terrain.

## 3D caves in all eight presets

All eight noise settings now use a `minecraft:range_choice` on **local solid terrain density**: beyond a protective near-surface interval or the deep-rock interval, the result is the ordinary terrain density **without evaluating the cave field**. Inside a bounded solid-depth band, `minecraft:min(terrain, cave)` uses the shared 3D spaghetti/cheese field. Cave density also smoothly adds near-roof and deep-rock shielding and a bedrock-floor bias. This design reduces unnecessary computation across the world height and is seed-/chunk-deterministic.

**Not simulated physical geology:** the cave networks are synthetic, not geologically surveyed karst, real aquifer water tables, or connected basin-scale river drainage. Underground fluid and full lithology remain incomplete.

## QA gates

- Static: all eight presets' references, interpolated procedural heights, no broken density IDs, same preliminary surface projection, cave shielding, and all vanilla materials.
- Real build: Java 21, NeoForge 21.1.249 `gradle build`.
- Live gameplay worldgen: NeoForge dedicated server `runServer` with generated Anvil region files; inspect surface neighboring-column deltas, 4-block grid boundary artifacts, subsurface void probes and spawn readiness.
- Future: generate **each of eight presets** under several seeds and compare geometry, caves, UI/client behavior, structure footing, biome appearance, memory and latency.

The static guard's bilinear continuity test checks interpolation as a **mathematical invariant**, not a substitution for actual saved-block results.

## Second actual server audit and v1.3.1 terrain retarget

The first real v1.3 Realism MAX server run on seed `785312` **passed** and saved 137 chunks / 14,592 surface columns. Recorded 28,816 neighboring columns: adjacent height change median **3 blocks**, p95 **10 blocks**. Means at boundaries of four-block XZ cells **3.555**, elsewhere **3.553** — a useful sign the old quart sampling steps were removed, **but average mountains were still far too steep**. Sampled top blocks were mostly snow (not tall tree canopies), so this is a meaningful physical landscape concern. Eight underground air/water probes out of 912 were detected; this proves some voids but does not prove connected caves.

The new v1.3.1 retunes **39 horizontal 2D noise frequencies in all seven procedural modes** to **35%** of their original v0.6 frequency (`xz_scale` multiplier 0.35); typical horizontal landforms are `1/0.35 ≈ 2.86` times wider while **vertical noise amplitudes, world Y bounds and Minecraft's 1 block = 1 m convention remain unchanged**. The measured USGS DEM pixels are not rescaled horizontally or vertically. Only the procedural fallback outside Big Sur expands.

**New slope distributions after v1.3.1 must be measured from saved Minecraft chunks; the v1.3 metrics above are a baseline, not a claim about the new build.** The old v0.6 original inputs remain in the `archive/` for exact comparison and regression tests assert all 39 XZ scales.

## Measured rollback and v1.3.2 interpolation-cell change

The v1.3.1 0.35× horizontal frequency adjustment **failed to improve slope distribution** in the same seed; even within **4,864 overlapping saved columns** from both world snapshots, v1.3 produced p50=2, p95=7 adjacent-block height changes, while v1.3.1 produced p50=3, p95=10 (the common-area arithmetic mean rose from 2.628 to 3.943). Its actual server did boot, but this outcome is **not** accepted as a terrain-smoothness fix. Different spawn coverages must not be directly compared without common-area matching.

**v1.3.2 reverts all 39 frequency changes to their original v0.6 inputs.** The original 1 block = 1 meter vertical scale and all 2D height amplitudes are preserved. Instead, the `NoiseSettings.noise.size_horizontal` parameter changes **1 → 4 for all eight preset modes**, so an `interpolated(flat_cache(...))` height field samples and linearly interpolates over **16 m cells** rather than **4 m cells**. This is a different mechanism: smoothing the final density sampling before voxelization instead of globally warping the geographical noise frequency.

Important: a 16 m *sampling interval* is **not** a 16 m block/world resolution. Minecraft still places full 1 m blocks at every coordinate. The expected result is lower local variance, but only the next actual saved-world test can confirm that. The same setting also affects cave interpolation width and DEM sampling (so inspect USGS 1:1 precision before release).

All seven planar noise-field archives and the published v1.1 JAR remain immutable. This branch is an experiment; the last proven official playable release is still v1.1.

## v1.3.3 candidate — conservative cave-connectivity experiment (pending live verification)

The shared Realism MAX 3D cave core feeds all eight presets. The two intersecting
spaghetti noise-sheet thickness offsets are adjusted from -0.145 to **-0.19**;
the cheese component's positive offset changes **0.47 → 0.37**. Those are
controlled changes to increase candidate subterranean spaces without altering
XZ terrain source frequencies, height amplitudes, surface protection, bedrock
shielding, or existing 0.25–4 solid-density routing gates. This is **not**
yet evidence of playable, connected caves: rerun the real server and compare
saved chunk measurements before accepting the experiment.

The saved-world QA now scans every available voxel between **20 and 160 blocks
beneath each local surface**, then computes six-neighbor 3D connected
components, component sizes, and components crossing 16-block chunk borders.
Missing Anvil sections are not interpreted as underground air. It also reports
chunk-border height gradients and isolated 1-block spikes. The scan is limited
by the saved-world footprint and roof-relative vertical window; it does not
prove complete connected networks, cave entrances, karst hydrology, or
playability. Use fresh worlds and matched-coordinate comparisons.

## Continental-specific cave overcarving guard (v1.3.3 follow-up; unverified until rerun)

A real dedicated-server scan of 1,935,360 subsurface voxels in Continental
at seed 785312 found a **26.2937% void fraction** and a single 480,326-voxel
component reaching 33 chunks. This is much larger than Realism MAX (2.1%) or
GeoReal Ultimate (2.9%) under the same sampling method, even though all servers
booted. A boot-only check would not have found this potential giant-cavern bug.

Continental now uses its **own copy of the 3D cave core** with unchanged
spaghetti tunnel width (-0.19) but a more restrictive cheese offset (**+0.62
instead of +0.37**). Other modes are unaffected. The suspected overcarving
requires a NEW matched-seed, saved-block remeasurement; there is no claim of
an established geological target void percentage or guaranteed fix.

### Second Continental correction — isolate the wide spaghetti intersection

The first scoped Cheese change to +0.62 did **not** improve the sampled
continental void fraction: the next saved-world scan saw 27.0024% underground
voids and a 480,460-voxel component across 33 chunks. This contradicts a
Cheese-only explanation and suggests the two wide spaghetti sheets are the
major driver. Their Continental-only offsets are reduced **-0.19 → -0.085**
(approximately 45% of the prior sheet thickness). The rest of the seven
presets and the measured Realism MAX shared core are unchanged. This is a
controlled hypothesis pending another same-seed real-server run, not a
claim that the causal mechanism has been conclusively isolated.

## v1.3.5 — evidence-based preset consolidation and compatibility

Audited the eight separate `world_preset` and `noise_settings` files, the actual saved-world checks, and each terrain height function. Four (Continental, Himalayan, Realistic Mountains, Ultimate) share exactly the same normalized height-expression structure (4 splines, one interpolated cached height signal), but differ in frequency/relief parameters; keeping all four in the default menu is not necessary. GeoReal has a substantially more involved 15-spline multi-scale terrain model, Realism MAX uses its own multi-field relief design, Grand Canyon has canyon-specific shaping and USGS Big Sur has measured DEM sampling. These are intentionally preserved as separate mainstream options.

| Original preset ID | Default menu | Alt/extended menu | Role |
|---|---|---|---|
| `realism_max` | Yes | Yes | General-purpose varied terrain |
| `georeal_ultimate` | Yes | Yes | Multi-scale relief/valleys |
| `himalayan` | Yes | Yes | Tall alpine mountain scenario |
| `grand_canyon` | Yes | Yes | Canyon landscape |
| `usgs_big_sur` | Yes | Yes | USGS DEM pilot |
| `continental` | No | Yes | Legacy low-frequency continental family |
| `realistic_mountains` | No | Yes | Legacy basic mountain family |
| `ultimate` | No | Yes | Legacy broad high-relief setting |

**Data compatibility rule:** Keep all eight original `world_preset`, `noise_settings`, individual density fields, archival JARs, and source-frequency identities. `minecraft:normal` contains only the five primary preset keys; `minecraft:extended` contains all eight. Both use `replace:false` to coexist with vanilla tags. This is a UI selector consolidation, **not** a destructive migration or unification of every old generator. Newly generated chunks under old IDs continue to use their original resources as defined by this experimental branch.

**QA bug discovered:** the earlier new-seed worldgen jobs reached a successful NeoForge startup and saved-world inspection, then failed a four-voxel mock test that asserted a 16-voxel-minimum cross-chunk result. The test fixture is corrected to span at least 16 contiguous voxels across a chunk border. `ci.yml` now executes all three QA suites (`test_density_continuity`, `test_cave_walkability`, `test_preset_catalog`) before Gradle compilation, to catch such errors more cheaply. No claim is made of zero bugs; perform GUI and saved-world tests before release.

## v1.3.6 candidate — cross-seed hollow mountain and missing surface water diagnosis

A later two-seed audit found Realism MAX at seed `20261012` had a **77.7911%** void fraction in the 20–160m-below-surface window, and seed `24681357` had **29.9225%**. Realistic Mountains also had 20–31% under those seeds. Therefore previous cavity settings (-0.19 shared spaghetti sheets; cheese +0.37) were unsafe in some worlds despite one attractive seed and successful server boot.

This experiment narrows the shared spaghetti intersection to **-0.085** and its cheese component to **+0.62**, reusing the controlled corrections that already removed Continental's 27% overcarving on seed 785312. Continental retains its independently registered cave core and is unchanged. All eight `sea_level` fields remain **63**, with vanilla water as the default fluid. No world heights, USGS DEM, or biome temperatures are remapped here.

Actual Anvil inspection now reports surface height percentiles and **water-on-surface counts** (as distinct from subterranean aquifers), and raises an explicit QA failure when its sampled 20–160m underground voxel void fraction reaches 20%. This is a conservative experiment gate and **not** a scientific global rock-porosity threshold. These changes do not on their own synthesize above-sea-level rivers. A surface river/lake mechanism must be separately planned and in-client tested; raising the sea level is expressly ruled out.

## v1.3.6 experimental hydrology: surface river-biome channels (new worlds only)

A Java `Feature<NoneFeatureConfiguration>` is registered as `realscale:river_channel`, selected as an optional **local_modifications** placed feature for vanilla river and frozen river biomes. It only executes when the active noise generator settings key belongs to `realscale:`, and explicitly excludes the USGS Big Sur measured DEM world. It inspects natural rock/soil in the *current chunk*, carves one block of shallow headroom and places water at the local high-altitude terrain surface, with a gravel bed; the frozen river counterpart creates ice. It refuses missing foundations and overwriting unrelated blocks. This is intended to restore visible high-altitude streams without raising the **63** sea level and without using the known-risk vanilla water LakeFeature in 1.21.x.

**Caveats:** this shallow biome-limited stream is not a full connected river basin, and fluid flow, freezing, cliffs, bank erosion, biome-frequency and cross-chunk water-level continuity must be tested in newly generated worlds before enabling it in a stable release. The structured saved-world water census can detect if the feature has zero practical effect; a successful NeoForge build alone does not prove visible rivers. The previous v1.1 release stays unmodified. Official NeoForge 1.21.1 biome modifier docs: https://docs.neoforged.net/docs/1.21.1/worldgen/biomemodifier/.

### Biome-aligned river inspection

The live Anvil QA now decodes actual per-section 4×4×4 biome palettes at each saved surface column. It reports the number of River/Frozen River surface cells, visible water/ice cells within those biomes, and visible river water above Y=70 (independent of the configured sea level). A dry-river warning is emitted when more than 100 river-biome cells are sampled with no visible fluid. This prevents assuming that a successful JSON registration produced an in-game surface river. The cave void-percent gate and sea-level-63 contract remain active.

### Further cross-seed cave suppression — v1.3.6 second experiment

The previous globally narrowed cave core still failed Realism MAX seed `20261012`: measured 35.3864% voids (down from the old 77.7911%, but still above the hard 20% QA gate). A second **experimental** reduction uses spaghetti intersection width **0.045** and cheese offset **0.75** in the shared core, leaving Continental's independent previously verified core as-is. This intentionally trades potential cave density for fewer implausibly hollow hills. It does not assert success until same-seed saved-world scanning demonstrates it, and will be rejected if it removes useful cross-chunk cave networks or harms other modes.

### Topology correction: do not open independent cheese megachambers

The shared cave core formerly used `min(spaghetti_intersection, cheese_density)`. This means **either** noise alone could yield a negative cave density, allowing broad Cheese zones to hollow mountains in some seeds. The new experimental expression uses `max(spaghetti_intersection, cheese_density)` and resets the spaghetti sheet offset to `-0.13` and cheese bias to `+0.05`: a cave exists only when the two tunnel axes overlap **and** local Cheese noise permits it. Cheese therefore modulates 3D tunnel continuity but cannot independently carve arbitrarily large empty chambers. This is a substantive topology fix rather than simply weakening all caves. The Continental-specific core is unchanged. Both extremely hollow and nearly cave-free saved worlds must be rechecked in multiple seeds; no density outcome is claimed before Minecraft server results.

### Frozen high-altitude stream correction

Live seed 785312 saved world showed 177 surface River-biome columns, **126 with water or ice** at Y>70, but zero exposed liquid surface columns: the top layer had become ice in the high mountains. The stream sculptor now places **two water layers** over a gravel bed before surface freezing, with a safe deeper solid-foundation check. Vanilla may freeze the upper water layer into ice (temperature-dependent), but water should remain directly beneath that ice. The Anvil QA now separately reports surface ice and ice-with-real-water-beneath counts. This is an empirically prompted cold-stream repair, not a claim about all river morphologies or a complete hydrological simulation.
