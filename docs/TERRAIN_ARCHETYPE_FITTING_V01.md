# RealScale 预设理论与地形拟合架构 v0.1

**状态：** 架构方案与离线拟合原型；尚未接入 NeoForge 的正式地形密度函数，也没有声称已获得珠峰或大峡谷的实测拟合结果。

## 1. 预设究竟是什么

预设不应是一整套互相独立的世界生成器。它应是一个简短的“地形主体配方”：选择地貌家族、若干由数据拟合的系数，以及必要的高度映射规则。

同一个世界生成管线负责连续性、世界尺度、海洋、河流、洞穴、生物群系、特殊盆地和稀有地貌。不同预设只改变世界主体的地形形态，不复制整套通用系统。

## 2. 精简后的四个玩家入口

1. **Natural Landscapes（自然地貌）**：默认的多尺度大陆、丘陵、平原和山地组合。
2. **Alpine Mountains（高山地貌）**：目标是从喜马拉雅/珠峰区域的真实 DEM 中拟合山脊、坡度、山谷和粗糙度系数；它不是珠峰地图的原样播放。
3. **Canyons & Valleys（峡谷与河谷）**：目标是从美国大峡谷区域的真实 DEM 中拟合高差、陡壁、平台和谷地统计特征；它不是把大峡谷高度图铺进无限世界。
4. **Measured Terrain（实测地形）**：唯一明确以指定地点的原始 DEM 作为局部地形输入的模式。它有真实数据覆盖边界，不能把覆盖范围之外的程序化补全称为实测地形。

“地球奇观”和“洞穴/海洋栖息地”属于可组合的功能层，不应仅仅因为它们有不同内容，就各自成为一套完整地形预设。旧世界预设 ID 继续保留；本次只整理新的创建世界入口，不删除历史资源。

## 3. 分层架构

- **L0 世界尺度与单位**：世界边界、水平尺度、垂直尺度、种子和海平面约定。
- **L1 通用地形骨架**：大陆/海盆、低频高度场、连续山脉、侵蚀与山谷基础场。所有地形家族共用实现。
- **L2 地形主体配方**：Natural、Alpine、Canyon。该层只提供家族类型和拟合系数。
- **L3 通用特殊地貌层**：盆地、冲积扇、盐沼/盐盘、喀斯特洼地、冰碛环、河口三角洲、石林等。由独立的放置/几何模块根据坐标、地形和生物群系条件决定是否生成，而不是复制到每个预设目录。
- **L4 气候与生态层**：生物群系过渡、洞穴生物群系、河流/水文、海洋栖息地和植被装饰。与 L2 分离，独立测试并组合。
- **L5 地表材质与方块映射**：统一的地表规则和原版方块映射。
- **L6 兼容层**：旧 ID、旧资源和旧存档路径保留；新的玩家可见入口指向简化后的规范预设。

分层的目标是“一个实现，多处组合”，而不是把同一组地形 JSON 复制成很多名字不同的目录。

## 4. 真实 DEM 如何变成可复用的生成模型

推荐管线：

1. **获取与追溯数据**：保留数据提供方、具体产品/文件 URL、采集/产品版本、坐标参考系、水平分辨率、垂直基准、单位和 SHA-256。
2. **质量检查**：检查 NoData、异常值、投影、米/英尺单位和垂直基准。不能把插值后的像素称作独立实地测量。
3. **提取形态特征**：高程分位数、P95–P05 relief、坡度分布、多尺度起伏 RMS、方向半变异函数、粗糙度尺度、山脊/谷地曲率比例。
4. **拟合紧凑参数**：把统计特征转换为参数文件，而不是把原始高度数组嵌进预设。
5. **程序化生成**：未来共享地形引擎读取拟合参数，按种子生成新噪声场、山脊/谷地形态和多尺度起伏。正常生成阶段不需要访问原始 DEM 文件。
6. **留出验证**：用未参与拟合的 DEM 子区和多个游戏种子，比较高差、坡度分布、尺度粗糙度和方向性；不能只检查一张截图或一个种子。

离线原型位于 research/v1.1/tools/fit_terrain_archetype.py。它输出拟合配置和统计摘要，不输出或保存完整原始高程网格。该原型尚未连接到 Minecraft DensityFunction，因此当前 JSON 是明确的模型交接契约，不代表游戏已自动使用这些系数。

### 参数化地形的概念形式

H(x,z) = A_macro · N_macro(x,z) + A_meso · N_meso(x,z) + A_micro · N_micro(x,z) + A_ridge · R(x,z) − A_valley · V(x,z) + A_strata · S(x,z)

其中 A_macro、A_meso、A_micro 等由数据拟合或通过后续校准确定；N_* 是由种子生成的程序化多尺度场；R、V、S 是可独立测试的山脊、谷地和地层形态核。单份 DEM 可以约束形态统计，但不能仅凭地形表面证明真实板块运动、降水或岩性因果关系。缺少岩性数据时，不应伪造“实测地层强度”。

## 5. 数据源候选与准确表述

- **珠峰/喜马拉雅**：可先评估 Copernicus DEM GLO-30（全球约 30 m 网格）作为区域尺度样本。它是数字表面模型，可能包含植被和建筑影响，不等同于裸地 LiDAR。官方说明：<https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM>
- **美国大峡谷**：优先评估 USGS 3DEP 的裸地 DEM；1/3 arc-second 产品约为 10 m，具体地点可能有更高分辨率的项目数据，必须以下载产品元数据为准。官方说明：<https://www.usgs.gov/3d-elevation-program/about-3dep-products-services>；下载入口：<https://www.usgs.gov/the-national-map-data-delivery/gis-data-download>

**当前仓库尚未包含已核验的珠峰或大峡谷 DEM，也没有相应拟合配置。** 现有 Big Sur 数据不能代替这两处数据。获取数据后再生成带来源信息的配置；不要先造一组参数再声称它来自真实地貌。

## 6. RealScale 与垂直高度限制

当前项目文档记录的 Overworld 范围为 Y=-64..2031，海平面约定为 Y=63。若同时要求水平 1 方块 = 1 米、垂直 1 方块 = 1 米，那么珠峰约 8.8 km 的海拔绝不可能被当前约 2,096 格的垂直范围无损容纳；仅珠峰山脚至峰顶的起伏也可能超过当前高度预算。

因此必须区分：
- **Measured Terrain**：忠实使用真实高程，超出世界边界就拒绝或缩小采样范围，不静默压缩。
- **Fitted Archetype**：从真实 DEM 学习形态参数，再生成程序化地形。若将其映射到当前游戏高度范围，必须显式记录垂直映射/压缩策略，不能继续宣称垂直 1:1。
- **完整垂直 1:1**：需要能容纳真实绝对海拔和 relief 的更高维度设计；当前世界高度并未满足这一要求。

水平比例、垂直比例、绝对高程基准和局部 relief 是四个不同概念，不能用“RealScale”一词把它们混为一谈。

## 7. 验收门槛

- 新世界菜单只显示四个规范入口；旧 ID 和历史资源仍可解析。
- 四个规范入口共用相同的通用生态/特殊地貌层，只切换地形主体配置。
- DEM 拟合文件记录数据来源、哈希、网格分辨率、单位和垂直基准。
- 拟合输出不包含原始高程网格；同一输入重复拟合得到可复现的 JSON。
- 对合成测试数据验证多尺度、坡度、方向半变异函数和家族选择。
- 真实 DEM 样本通过独立来源核验后，才能发布 Everest/Himalaya 或 Grand Canyon 拟合配置。
- NeoForge 构建、多个种子的服务器生成、区块边界、海洋、河流、洞穴、结构落地和存档兼容分别验证。离线拟合测试通过不等于游戏运行时已通过。
